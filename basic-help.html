1. Data And Variables

  • LET name = expr: Assign expression result to a variable.
  • READ("$30") INTO name or LET name = READ("$30"): Read a GRBL setting from $$.
  • SETTING("$30") INTO name or LET name = SETTING("$30"): Alias for READ.
  • INPUT name, INPUT name, "Prompt", name = INPUT("Prompt"), LET name = INPUT("Prompt"): Ask user for input via a text field.
  • LET name = FORM(msgExpr, val1, val2): Show a button-choice dialog. The message is any expression — literal string, concatenation, variable references, etc. Each [Label] token in the rendered message becomes a button; the matching val argument is the numeric value returned when clicked. Numbers are implicitly converted to text so STR() is optional. Use \, to include a literal comma. Can also be written as INPUT(FORM(...)).

FORM() Button Dialog

FORM() shows a modal dialog with clickable buttons derived from [Label] tokens in the rendered message. The message argument is evaluated as a full expression at runtime, so you can embed variable values using string concatenation (&) or any other supported expression. Numbers are implicitly converted to text — STR() is optional inside the message. The remaining comma-separated arguments are the numeric values each button returns, matched left-to-right with the labels. Use \, to embed a literal comma in the message without splitting the argument list.

Two forms are supported:

  • LET x = FORM(...) — buttons only, no text field. The user must click a button. Use this for clear-cut choices where only the predefined values make sense.
  • LET x = INPUT(FORM(...)) — same buttons plus a text field. Buttons act as shortcuts that immediately resolve the dialog; the user can also type a custom value and press Enter. Use this when a free-form value should be possible alongside the presets.
; TITLE: Section 1 — Variables and Dialogs Demo
; VERSION: 1.0
; DESCRIPTION: Explores LET, SETTING/READ, INPUT, and FORM() dialogs.
; DESCRIPTION: Uses the {accel_setting} var — change it to any $N number you want to inspect.
; DESCRIPTION: Success: each dialog resolves, values are printed, original setting is restored.
; VAR accel_setting=$120
10 REM --- LET: basic variable assignment ---
20 LET greeting = "GCOM"
30 LET revision = 1
40 PRINT greeting & " v" & revision

50 REM --- SETTING/READ: read a live controller value ---
60 LET orig_accel = SETTING("{accel_setting}")
70 PRINT "Current {accel_setting} = " & orig_accel & " mm/s^2"

80 REM --- INPUT: free-text prompt ---
90 INPUT run_label, "Enter a label for this run:"
100 PRINT "Run label: " & run_label

110 REM --- FORM(): button-choice dialog, static message ---
120 LET mode = FORM("Select test mode [Quick] [Full] [Abort]", 1, 2, 0)
130 IF mode = 0 THEN GOTO 9000
140 PRINT "Mode: " & mode

200 REM --- FORM() with dynamic message (current setting embedded) ---
210 LET cur = SETTING("{accel_setting}")
220 LET accel_choice = FORM("{accel_setting} is " & cur & " mm/s^2. [Keep] [Double] [Abort]", cur, cur * 2, 0)
230 IF accel_choice = 0 THEN GOTO 9000

300 REM --- INPUT(FORM()): buttons as shortcuts + free text entry ---
310 LET new_val = INPUT(FORM("Apply {accel_setting}=" & accel_choice & "? [Apply] [Keep] — or type value:", accel_choice, cur))
320 IF new_val = cur THEN GOTO 400
330 SEND "{accel_setting}=" & new_val TIMEOUT 2000 REQUIRE_OK
340 PRINT "Updated {accel_setting}. Restoring original..."
350 SEND "{accel_setting}=" & orig_accel TIMEOUT 2000 REQUIRE_OK
360 PRINT "Restored {accel_setting} = " & orig_accel

400 PRINT "Section 1 demo complete."
410 END

9000 PRINT "Demo aborted."
9010 END

2. Machine I/O Commands

  • SEND expr: Send a command string to GRBL. Expression is converted to text.
  • SEND expr TIMEOUT expr: Wait for terminal acknowledgement up to timeout ms.
  • SEND expr REQUIRE_OK: Fail statement if no ok/error/ALARM acknowledgement arrives.
  • SEND expr TIMEOUT expr REQUIRE_OK: Use both options together.
  • SEND expr BUFFERED: Stream a normal line-based GRBL command using host-side RX buffer accounting. Buffered sends do not wait for machine idle after each line; use WAIT_IDLE after the final buffered command in a batch to flush all acknowledgements and then wait for motion to finish.
  • SENDBUFF expr: Legacy alias for SEND expr BUFFERED. Prefer SEND ... BUFFERED in new scripts.
  • SENDACK expr or SENDACK expr timeoutMs: Legacy alias for SEND expr TIMEOUT timeoutMs REQUIRE_OK. Prefer SEND ... REQUIRE_OK in new scripts.
  • HOLD, RESUME, STATUS, SOFT_RESET: Realtime control commands.

STATUS is also how the runtime learns Bf: capacity fields (planner slots and serial RX bytes). Call STATUS early in scripts that use buffered streaming so capacity is learned before large batches begin.

Rule of thumb for sender mode selection: serial buffer below ~50% utilization usually benefits from buffered sends; higher pressure is often as fast or safer with strict ACK-gated sends (REQUIRE_OK semantics). That larger-buffer pattern is common on modern ESP32-class firmware (for example FluidNC and many grblHAL targets).

; TITLE: Section 2 — Machine I/O Test
; VERSION: 1.0
; DESCRIPTION: Tests SEND/REQUIRE_OK, STATUS, HOLD, and RESUME.
; DESCRIPTION: In laser mode G1+F is required to activate the output — M3 alone is not enough.
; DESCRIPTION: Set spindle_speed to a safe S-value (0 = off). Set feed_rate to a safe feed.
; DESCRIPTION: Success: M3 G1 acknowledged, STATUS returns a state frame, HOLD/RESUME cycle, M5 acknowledged.
; VAR spindle_speed=0
; VAR feed_rate=100
10 REM spindle_speed = S-value; feed_rate = F-value for laser mode
20 LET speed = {spindle_speed}
30 LET feed = {feed_rate}
40 PRINT "Starting I/O test at S" & speed & " F" & feed & "..."
50 REM Laser mode requires G1 + F to actually enable output; safe for spindle too
60 SEND "M3 G1 F" & feed & " S" & speed TIMEOUT 1500 REQUIRE_OK
70 PRINT "Success check: M3 G1 acknowledged at S" & speed & " F" & feed
80 STATUS
90 WAIT_FOR_LINE("^<", 2000) INTO st
100 VERIFY st <> "", "status_frame" HALT
110 PRINT "Success check: STATUS returned: " & st
120 HOLD
130 PRINT "Success check: controller should enter Hold state."
140 WAIT 500
150 RESUME
160 PRINT "Success check: controller should leave Hold and continue."
170 SEND "M5" TIMEOUT 1500 REQUIRE_OK
180 PRINT "Test complete: M5 acknowledged."
190 END

3. Timing, State, And Incoming Lines

  • WAIT expr: Delay for N ms.
  • WAIT_IDLE or WAIT_IDLE timeoutMs: Wait until machine is idle.
  • WAIT_STATE target or WAIT_STATE target TIMEOUT timeoutMs: Wait for specific state.
  • LET name = WAIT_FOR_LINE(pattern, timeoutMs) or WAIT_FOR_LINE(pattern, timeoutMs) INTO name: Block until an incoming serial line matches pattern (regex or plain substring). Returns the matched line, or "" on timeout. Pass 0 for no timeout.
  • LET name = READ_LINE(timeoutMs) or READ_LINE(timeoutMs) INTO name: Return the very next incoming serial line regardless of content; "" on timeout.
; TITLE: Section 3 — Timing, State and Line-Capture Test
; VERSION: 1.0
; DESCRIPTION: Exercises WAIT, WAIT_IDLE, WAIT_STATE, WAIT_FOR_LINE, and READ_LINE.
; DESCRIPTION: Set wait_ms to a short pause before the idle checks — 0 is fine if machine is already idle.
; DESCRIPTION: Success: each timing gate passes and every WAIT_FOR_LINE / READ_LINE returns a non-empty line.
; VAR wait_ms=250
10 WAIT {wait_ms}
20 WAIT_IDLE 20000
30 WAIT_STATE "idle" TIMEOUT 5000
40 PRINT "Success check: WAIT + WAIT_IDLE + WAIT_STATE completed."
50 REM For command acknowledgements use REQUIRE_OK
60 SEND "$I" TIMEOUT 2000 REQUIRE_OK
70 PRINT "Success check: $I acknowledged."
80 REM WAIT_FOR_LINE only catches lines arriving after STATUS is sent
90 STATUS
100 WAIT_FOR_LINE("^<", 2000) INTO status_line
110 VERIFY status_line <> "", "wait_for_line_into" HALT
120 PRINT "Success check: WAIT_FOR_LINE INTO: " & status_line
130 STATUS
140 LET status_line2 = WAIT_FOR_LINE("^<", 2000)
150 VERIFY status_line2 <> "", "wait_for_line_let" HALT
160 PRINT "Success check: WAIT_FOR_LINE LET: " & status_line2
170 REM READ_LINE returns the very next incoming line
180 STATUS
190 LET next_line = READ_LINE(1500)
200 VERIFY next_line <> "", "read_line_let" HALT
210 PRINT "Success check: READ_LINE LET: " & next_line
220 STATUS
230 READ_LINE(1500) INTO line2
240 VERIFY line2 <> "", "read_line_into" HALT
250 PRINT "Success check: READ_LINE INTO: " & line2
260 PRINT "Section 3 test complete."
270 END

A timeout ("" result) fails the matching VERIFY ... HALT check and stops the script immediately — no numbered error branches needed. Failures also appear in the Checks block on REPORT.

4. Connection Management

Scripts can open a connection themselves using CONNECT or CONNECT WS, enabling fully scriptable connection sequences without using the Connection sidebar. A script containing either form may run even when no connection is currently open.

USB / Serial

  • CONNECT: Show the browser serial port picker and connect at 115200 baud with default settings.
  • CONNECT BAUD expr: Connect at the specified baud rate.
  • CONNECT BAUD expr DTR "mode": Apply a DTR signal mode after opening. Accept: "default", "pulse", "low", "high".
  • CONNECT BAUD expr DTR "mode" WAIT expr: Pause N ms post-connect (useful when a DTR pulse reboots the controller — gives it time to boot).
  • CONNECT … OBSERVE: Connect in observe-only mode; no commands are sent.

All keyword arguments are optional and combinable in any order. If the user cancels the port picker the script stops gracefully.

10 REM USB/Serial connection test
20 REM Success means: banner or status arrives and connection is then closed cleanly.
30 CONNECT BAUD 115200
40 STATUS
50 LET reply = WAIT_FOR_LINE("GrblHAL|Grbl|FluidNC|<", 3000)
60 VERIFY reply <> "", "controller_banner" HALT
70 PRINT "Success check: connected and received: " & reply
80 DISCONNECT
90 PRINT "Success check: serial connection closed."
100 END

WebSocket (WiFi / FluidNC)

Use CONNECT WS to connect to a FluidNC or ESP32-based controller over WiFi. No browser port picker appears — the script connects directly to the address you supply.

  • CONNECT WS "host": Connect to host on port 80 (FluidNC v4.0+ default).
  • CONNECT WS "host" PORT expr: Connect to host on the specified port. Use port 81 for FluidNC versions earlier than v4.0.
  • DISCONNECT: Close either a serial or WebSocket connection.

host is an IP address or hostname, e.g. "192.168.1.100". The script stops if the WebSocket connection fails (unreachable host, refused connection, etc.).

10 REM WebSocket connection test
20 REM Success means: handshake line arrives, firmware info is returned, then clean disconnect.
30 CONNECT WS "192.168.1.100"
40 REM Use PORT 81 for older FluidNC: CONNECT WS "192.168.1.100" PORT 81
50 LET reply = WAIT_FOR_LINE("GrblHAL|Grbl|FluidNC|<", 5000)
60 VERIFY reply <> "", "ws_handshake" HALT
70 PRINT "Success check: WS connected and received: " & reply
80 SEND "$I" TIMEOUT 3000 REQUIRE_OK
90 LET info = WAIT_FOR_LINE("\[VER:", 3000)
100 VERIFY info <> "", "firmware_ver_line" HALT
110 PRINT "Success check: firmware info line: " & info
120 DISCONNECT
130 PRINT "Success check: WS connection closed."
140 END

5. Runtime Settings

Script-level settings tune timing and buffer parameters. All settings reset to their defaults at the end of every script run, so changes never leak into subsequent runs.

  • SET SEND_DELAY expr: Pause in ms appended after each SEND (default 0). Increase if your controller or transport benefits from extra spacing between commands.
  • SET ACK_TIMEOUT expr: Default acknowledgement wait in ms (default 12000). Affects bare SEND without an explicit TIMEOUT, and WAIT_FOR_LINE / READ_LINE without an explicit timeout argument.
  • SET RX_BUFFER expr: Fallback RX buffer byte limit when no Bf: report has been observed (default 64). Controls the SEND … BUFFERED window. Once a real Bf: serial value is observed, runtime capacity estimates use observed values instead of this fallback.
  • SET SEND_MODE expr: Select send routing policy: BUFFERED (prefer buffered streaming), REQUIRE_OK (strict ack-gated sending), or AUTO (buffered while host-side serial pressure is low, otherwise REQUIRE_OK). If no serial Bf: has been observed yet, AUTO uses the configured RX buffer fallback estimate.
  • SET BANNER_TIMEOUT expr: Milliseconds to wait for a startup banner after CONNECT (default 3000).
  • SET READY_SETTLE expr: Post-connect idle settle time in ms (default 150).
  • SET SEQUENCE_DELAY expr: Inter-command spacing in ms during startup sequences (default 450).
  • SET STATUS_DELAY expr: Delay in ms between status polls (default 600).
  • RESET_SETTINGS: Restore all runtime settings to their defaults mid-script.

Why SEND_MODE AUTO exists: controller families differ a lot in serial buffering and live queue pressure. AUTO keeps one script portable by dynamically choosing BUFFERED or REQUIRE_OK behavior from observed capacity and current in-flight load instead of forcing authors to hardcode per-firmware send strategy.

REM Zero all delays for a fast benchmark run
10 SET ACK_TIMEOUT 30000
20 STATUS
30 LET serial_cap = BF_SERIAL()
40 LET planner_cap = BF_PLANNER()
50 PRINT "Serial buffer: " & serial_cap & " bytes"
60 PRINT "Planner slots: " & planner_cap
70 SET SEND_MODE AUTO
80 FOR i = 1 TO 100
90 SEND "G0 X" & i BUFFERED
100 NEXT i
110 WAIT_IDLE 30000
120 RESET_SETTINGS
130 PRINT "Done — settings restored to defaults"
140 END

6. User Messaging And Results

  • PRINT [expr]: Log a message to terminal. Omit the expression for a blank separator line.
  • CONFIRM expr: Show confirmation dialog. If canceled, script stops.
  • PAUSE: Pause script until resumed.
  • RESULT name, expr: Save a named result value.
  • REPORT: Print all saved results, followed by a Checks block listing every VERIFY check outcome — see Section 8: Expression Functions.
  • stmtA : stmtB: Statement chaining on one numbered line. Execution is left-to-right; colons inside quoted strings are ignored.
10 LET speed = 1200
20 PRINT "Starting run"
30 RESULT "target_speed", speed
40 CONFIRM "Run with speed " & speed & "?"
50 REPORT
60 END

7. Program Flow

  • FOR name = start TO end [STEP step] and NEXT [name]: Counter loop with optional explicit step.
  • IF condition THEN GOTO line: Conditional jump. Also accepts IF cond THEN LET, IF cond THEN PRINT, IF cond THEN GOSUB, IF cond THEN VERIFY, and IF cond THEN END as single-line inline statements.
  • AND / OR: Logic operators in IF and VERIFY conditions. AND binds tighter than OR. Operands are comparisons: IF state = "Alarm" OR state = "Hold" THEN GOTO 9000. Parentheses are honored when grouping comparison operands, but comparisons cannot be nested inside arithmetic — build boolean sums by combining comparisons with AND/OR instead.
  • GOTO line: Unconditional jump.
  • GOSUB line and RETURN: Subroutine call/return.
  • END: Stop script.

For self-marking checks with automatic counting and reporting, use VERIFY — see Section 8: Expression Functions.

10 LET sum = 0
20 FOR i = 1 TO 5
30 LET sum = sum + i
40 NEXT i
50 PRINT "Sum = " & sum
60 END

8. Expression Functions

  • PI: Circle constant (3.141592653589793).
  • STR(expr): Convert value to string.
  • LEN(text): String length.
  • TRIM(text): Trim leading/trailing whitespace.
  • UPPER(text): Convert text to uppercase.
  • LOWER(text): Convert text to lowercase.
  • SUBSTR(text, start[, length]): 1-based substring with optional length.
  • CONTAINS(text, needle): Returns 1 when found, otherwise 0.
  • STARTS_WITH(text, prefix): Returns 1 when true, otherwise 0.
  • ENDS_WITH(text, suffix): Returns 1 when true, otherwise 0.
  • REPLACE(text, find, with[, maxReplacements]): Replace matches in text. Omit maxReplacements to replace all.
  • SPLIT_COUNT(text, delim): Number of tokens after split.
  • SPLIT_PART(text, delim, index[, fallback]): 1-based token lookup with optional fallback.
  • SPLIT_INTO(text, delim, prefix): Writes prefix_COUNT and prefix_1..prefix_N variables. Returns token count.
  • ABS(expr): Absolute value.
  • INT(expr): Integer truncation.
  • TRUNC(expr): Integer truncation (alias of INT).
  • CEIL(expr): Round up to next integer.
  • FLOOR(expr): Round down to previous integer.
  • SIGN(expr): Returns -1, 0, or 1 based on value sign.
  • ROUND(value[, digits]): Round to nearest integer or to N decimal places.
  • SQRT(expr): Square root.
  • HYPOT(x, y): 2D hypotenuse length.
  • EXP(expr): Exponential function (e^x).
  • LOG(expr): Natural logarithm (ln).
  • LN(expr): Alias for natural logarithm.
  • LOG10(expr): Base-10 logarithm.
  • CLAMP(value, min, max): Bound a value to a range. Prefer over nested IF checks for capping feeds, powers, and computed limits — e.g. LET eff_feed = CLAMP(target_feed, 0, v_max_rate).
  • MAX(a, b): Larger of two values.
  • MIN(a, b): Smaller of two values.
  • MOD(a, b) or a % b: Remainder (modulo).
  • SIN(angleDeg): Sine of an angle in degrees.
  • COS(angleDeg): Cosine of an angle in degrees.
  • TAN(angleDeg): Tangent of an angle in degrees.
  • SINH(value), COSH(value), TANH(value): Hyperbolic trig.
  • ASIN(value): Inverse sine, returns degrees.
  • ACOS(value): Inverse cosine, returns degrees.
  • ATAN(value): Inverse tangent, returns degrees.
  • ATAN2(y, x): Inverse tangent with quadrant handling, returns degrees.
  • ASINH(value), ACOSH(value), ATANH(value): Inverse hyperbolic trig.
  • RAD(degValue): Convert degrees to radians.
  • DEG(radValue): Convert radians to degrees.
  • RND(max): Random integer from 1 to max.
  • GCODE_PARAM(key[, fallback]): Read cached CNC-style parameters such as #100 or #<_x> with optional default fallback — e.g. LET work_x = GCODE_PARAM("#<_x>", 0).
  • BF_SERIAL(): Estimated serial RX capacity in bytes. Uses observed Bf: serial values; if none have been observed yet, returns the current SET RX_BUFFER fallback.
  • BF_PLANNER(): Estimated planner capacity in slots from observed Bf: planner values. Returns -1 when planner data is unavailable.
  • STATE() or STATE: Current machine state string.
  • BENCH_LAST_MS(): Wall-clock duration of the most recently completed BENCH START … BENCH END pair, in milliseconds. See Section 9: Benchmark Markers for the full marker protocol including BENCH META chart configuration.
  • CLOCK(): Current timestamp in milliseconds (performance.now()). Store the result in a variable to use as a lap-timer start point.
  • ELAPSED(t0): Milliseconds elapsed since t0 (a value previously captured by CLOCK()). Returns a number so it can be used in further math.
  • FORMAT_MS(ms): Format a millisecond number as a human-readable string — "456 ms" or "1.23 s". Returns a string; use only inside PRINT or string concatenation.

VERIFY — Self-Marking Checks

VERIFY evaluates a condition (same grammar as IF conditions) and records the outcome under a quoted label. Passing checks are counted silently; failing checks are counted and highlighted. All named checks appear automatically in a Checks block when REPORT runs.

  • VERIFY expr, "label": Check, record, and continue regardless of outcome.
  • VERIFY expr, "label" HALT: Check and record, then stop the script immediately if the check fails. Use for preconditions that must hold before continuing (e.g. machine Idle before motion).
  • VERIFY expr, "label" ASK: Check and record, then on failure show a dialog where the operator chooses Continue or Cancel Script. Not suitable for unattended runs.
  • Conditions support AND/OR: VERIFY pos_type = "MPos" OR pos_type = "WPos", "pos_type".
  • PASS_COUNT / FAIL_COUNT: Read-only variables derived from the recorded checks. They cannot be assigned with LET.
  • VERIFY also works inline: IF cond THEN VERIFY other_cond, "label".

Use VERIFY for verifiable outcomes and IF ... THEN PRINT for observations that are informational rather than right-or-wrong.

This deterministic script self-marks expected versus actual results. It uses one fabricated sentence for simple string functions, then a canned status line for SPLIT_COUNT, SPLIT_PART, and SPLIT_INTO parsing checks.

; TITLE: Section 8 - Expression Functions Self-Marking Test
; VERSION: 2.0
; DESCRIPTION: Deterministic self-marking test of the expression functions.
; DESCRIPTION: Each check is a VERIFY - failures are counted, recorded, and listed by REPORT.
; DESCRIPTION: Success means FAIL_COUNT = 0 and FINAL RESULT: PASS.
; VAR expected_state=Idle
; VAR expected_sentence_len=28
; VAR expected_x=0.000
; VAR expected_y=0.000
; VAR expected_z=5.000
10 PRINT "Starting Section 8 self-marking test..."
20 LET sentence = "The cow jumped over the moon"
30 VERIFY LEN(sentence) = {expected_sentence_len}, "sentence_len"
40 VERIFY CONTAINS(sentence, "cow") = 1, "contains_cow"
50 VERIFY STARTS_WITH(sentence, "The") = 1, "starts_with_The"
60 VERIFY ENDS_WITH(sentence, "moon") = 1, "ends_with_moon"
70 VERIFY SPLIT_PART(sentence, " ", 2, "") = "cow", "split_part_word2"
80 VERIFY REPLACE(sentence, "cow", "owl") = "The owl jumped over the moon", "replace_sentence"
90 VERIFY UPPER(sentence) = "THE COW JUMPED OVER THE MOON", "upper_sentence"
100 VERIFY LOWER(sentence) = "the cow jumped over the moon", "lower_sentence"
110 LET status = "<Idle|MPos:0.000,0.000,5.000|Bf:35,7680|FS:0,0|Pn:P|CL:0,100|PS:2,1|ER:0,0>"
120 VERIFY CONTAINS(status, "MPos") = 1, "fixture_status_shape" HALT
130 LET clean = TRIM(status)
140 LET token_count = SPLIT_INTO(clean, "|", "fld")
150 VERIFY SPLIT_COUNT(clean, "|") = token_count, "split_count_match"
160 VERIFY SPLIT_PART(clean, "|", 1, "") = "<" & {expected_state}, "parsed_state"
170 VERIFY token_count >= 8, "field_count_min"
180 LET pos_type = SPLIT_PART(SPLIT_PART(clean, "|", 2, ""), ":", 1, "")
190 VERIFY pos_type = "MPos" OR pos_type = "WPos", "pos_type"
200 LET pos_values = SPLIT_PART(SPLIT_PART(clean, "|", 2, ""), ":", 2, "")
210 VERIFY SPLIT_PART(pos_values, ",", 1, "") = "{expected_x}", "parsed_x"
220 VERIFY SPLIT_PART(pos_values, ",", 2, "") = "{expected_y}", "parsed_y"
230 VERIFY SPLIT_PART(pos_values, ",", 3, "") = "{expected_z}", "parsed_z"
240 VERIFY CONTAINS(clean, "Bf:") = 1, "bf_fields_present" ASK
250 IF CONTAINS(clean, "Pn:") = 1 THEN PRINT "NOTE: Pn: pin field active - input pin state reported"
260 RESULT "tokens_parsed", token_count
270 PRINT "Summary: " & PASS_COUNT & " passed, " & FAIL_COUNT & " failed"
280 REPORT
290 IF FAIL_COUNT = 0 THEN PRINT "FINAL RESULT: PASS"
300 IF FAIL_COUNT > 0 THEN PRINT "FINAL RESULT: FAIL"
310 END

9. Benchmark Markers

BENCH markers let a script time arbitrary sections of work and stream live results to the Preview window's Benchmark chart. All BENCH directives are emitted as plain PRINT output — the app intercepts them during script execution.

BENCH META key: value

Sets one chart metadata property for the current run. Send these before the first BENCH START to configure how the Preview chart is drawn. Keys are case-insensitive. Available keys:

  • title: … — chart title shown in the Preview banner.
  • subtitle: … / description: … — secondary label text.
  • x: fieldName or xfield: fieldName — which field from BENCH START/END to map on the X axis. Defaults to sampleIndex (1-based order of completed samples).
  • y: fieldName or yfield: fieldName — which field to map on the Y axis. Defaults to elapsedMs. Use a comma-separated list, such as y: throughput, peak, to plot multiple Y fields from each sample on the same chart.
  • series: fieldName or seriesfield: fieldName — field whose value splits samples into named series (one chart line per distinct value). Omit for a single series.
  • colorby: fieldName — field whose value controls line and marker colour. This lets multiple Y fields for the same distance share one colour.
  • xlabel: … — X axis label shown on the chart.
  • ylabel: … — Y axis label shown on the chart. Defaults to Elapsed (ms).
  • chart: line or charthint: line — chart rendering hint (currently only line is supported).

BENCH RECORDS template

Declares how each completed sample is rendered as a pipe-separated record in the Preview sample list and in the AI selection payload. Each BENCH RECORDS line adds one segment template. Templates are run-global (like BENCH META); lines accumulate, and BENCH RECORDS CLEAR resets them. If no templates are declared, the app falls back to its built-in default label format.

  • Templates contain plain {fieldname} references only — no expressions or conditionals. Compute derived values in the script with LET and include them on the BENCH END line.
  • {_elapsed} (app-measured ms) and {_sampleIndex} (1-based sample order) are built-in fields; script field names must not start with _.
  • If any field in a segment is missing or non-numeric, that whole segment is dropped from the record.
  • Remaining segments are joined with | at render time.
  • Fields referenced only in BENCH RECORDS templates are resolved from sample data at render time and do not need ; VAR declarations — they are excluded from the Variables list and share-link overrides.
; Tape record definition (plain field references only)
30 PRINT "BENCH RECORDS {distance} mm @ {accel} accel"
31 PRINT "BENCH RECORDS {_elapsed} ms"
32 PRINT "BENCH RECORDS {batch} cycles"
33 PRINT "BENCH RECORDS {travel} mm travel"
34 PRINT "BENCH RECORDS {mm_per_min} mm/min"
35 PRINT "BENCH RECORDS peak {peak_mm_min} mm/min"
36 PRINT "BENCH RECORDS {avg_peak_pct}% of peak"

; Derived values computed in the script and emitted on BENCH END
1080 LET travel_mm = batch * 2 * distance
1081 LET avg_peak_pct = ROUND(mm_per_min / peak_mm_min * 100, 0)
1082 PRINT "BENCH END distance=" & distance & " accel=" & accel & " batch=" & batch & " travel=" & travel_mm & " mm_per_min=" & mm_per_min & " peak_mm_min=" & peak_mm_min & " avg_peak_pct=" & avg_peak_pct

BENCH STYLE yField property: value

Sets display style for one Y field. Available properties:

  • marker: dot, marker: x, or marker: none — point marker shape.
  • line: on or line: off — whether points for that Y field are connected by a line.

BENCH START key=value …

Opens a timed window. The key-value pairs can be any arbitrary fields; they are attached to the resulting sample record and can be referenced in BENCH META axis mappings. The same set of keys is typically echoed in the matching BENCH END line.

BENCH END key=value …

Closes the timed window and records the sample. The app measures the wall-clock elapsed time as elapsedMs. All key-value fields from both the START and END lines are merged into the sample record, alongside elapsedMs, startedAtIso, and endedAtIso. The elapsed time is made available to the script via BENCH_LAST_MS(). The completed record is streamed to the Preview window immediately.

The Preview Benchmark chart auto-scales to all recorded points and renders each series in a distinct colour. The Copy JSON button in Preview exports the full record set with metadata in a self-describing format ready for downstream analysis or AI-assisted visualisation.

Note: the example below sends real motion commands. The machine must be connected and in Idle state before running. A FORM() confirmation at line 5 gates the motion so the script stops cleanly if cancelled.

10. Import Header Format

Plain-text GCOM script imports can start with a short metadata header before the first numbered GCOM script line. Header lines use a ; prefix — the Save GCOM button generates this format automatically. The importer also accepts the legacy REM prefix for backward compatibility.

  • ; TITLE: ..., ; VERSION: ..., and ; AUTHOR: ... set the matching app fields.
  • ; DESCRIPTION: ... can appear more than once. Repeated lines are joined into a multiline description in the app.
  • Rendered descriptions support both simple placeholders like {feed} and inline expression placeholders like {{min_batch_count * 2}}.
  • ; VAR name=value seeds a variable default. Placeholder names from the script or description are also added if they are missing.
  • VAR value types and {name} substitution: a value that looks like a number (0.000, 120) is numeric; anything else is text. Wrap the value in quotes to declare it as text even if it looks numeric (; VAR part_no="1234").
    • Outside string literals: numeric placeholders substitute bare (WAIT {wait_ms}); text placeholders substitute as a quoted, escaped string literal, so VERIFY STATE() = {expected_state} works when expected_state is Idle.
    • Inside string literals: placeholders always substitute their raw text: SEND "M3 S{power}" and "<{expected_state}" embed naturally without double quoting.
    • Values containing quotes or backslashes are escaped automatically at substitution.
  • If no title header exists, import falls back to the filename.
  • Clipboard paste detects G-code patterns and can convert macros/subroutines into step-by-step GCOM automatically.

12. Example: X-Axis Max travel Speed and Acceleration Finder

This example ramps $120 upward while repeatedly running fast back-and-forth X travel moves, asks the operator after each pass whether the axis sounded bad or skipped, retests the edge with a finer step, and reports a conservative recommendation. $110 (max X feed rate) is temporarily raised so the test feedrate is not clamped during the run, then restored at the end.

After reporting results, the script compares the original and suggested $120 values and asks whether to apply the suggested value now or keep the original setting.

Note: this script uses button-based FORM() prompts so operator decisions are explicit during the test flow.

; TITLE: X-Axis Max travel Speed and Acceleration Finder
; AUTHOR: GitHub Copilot
; VERSION: 4
; DESCRIPTION: Raises X acceleration by {coarse_step} starting at {start_accel} while running fast X travel moves until motion sounds bad or skips, then refines by {fine_step}.
; DESCRIPTION: Estimates peak midpoint travel speed and asks whether to apply the suggested $120 setting or keep the original.
; VAR start_accel=800
; VAR coarse_step=200
; VAR fine_step=20
; VAR max_accel=4000
; VAR x_travel=400
; VAR x_feed=70000
; VAR repeats=1
; VAR idle_timeout=20000
; VAR settle_ms=250

10 PRINT "X-axis max travel speed and acceleration test"
20 PRINT "Clear the machine so X can move back and forth safely."

40 LET proceed = FORM("X-axis travel test ready. [Begin Test] [Cancel]", 1, 0)
50 IF proceed <> 1 THEN GOTO 9000
60 LET original_accel = SETTING("$120")
70 LET original_feed = SETTING("$110")
80 LET last_good = 0 : LET first_bad = 0
90 LET fine_good = 0 : LET fine_bad = 0
100 LET recommended = 0 : LET current_accel = 0 : LET answer = 0
110 LET max_tested_accel = 0
120 LET max_mid_speed_mm_min = 0 : LET apply_choice = 0
130 PRINT "Original $120 = " & original_accel
140 PRINT "Original $110 = " & original_feed
200 PRINT "Temporarily setting feed speed high"
210 SEND "$110=60000" TIMEOUT 2000 REQUIRE_OK
220 SEND "G21" TIMEOUT 1000 REQUIRE_OK
230 SEND "G91" TIMEOUT 1000 REQUIRE_OK
240 PRINT "Starting coarse search..."

250 FOR test_accel = {start_accel} TO {max_accel} STEP {coarse_step}
260 LET current_accel = test_accel
270 LET max_tested_accel = MAX(max_tested_accel, current_accel)
280 GOSUB 1000
290 IF answer <> 0 THEN GOTO 410
300 LET last_good = current_accel
310 NEXT test_accel
320 PRINT "No failure found up to max tested value."
330 LET recommended = last_good
340 GOTO 710

410 LET first_bad = current_accel
420 PRINT "First bad coarse value = " & first_bad
430 IF last_good = 0 THEN GOTO 920
440 LET fine_good = last_good
450 PRINT "Starting fine search..."
460 FOR test_accel = last_good + {fine_step} TO first_bad STEP {fine_step}
470 LET current_accel = test_accel
480 LET max_tested_accel = MAX(max_tested_accel, current_accel)
490 GOSUB 1000
500 IF answer <> 0 THEN GOTO 610
510 LET fine_good = current_accel
520 NEXT test_accel
530 LET recommended = fine_good
540 GOTO 710

610 LET fine_bad = current_accel
620 LET recommended = fine_bad - {fine_step}
630 PRINT "First bad fine value = " & fine_bad
640 GOTO 710

710 LET max_mid_speed_mm_min = SQRT(max_tested_accel * {x_travel}) * 60
720 SEND "$110=" & original_feed TIMEOUT 2000 REQUIRE_OK
730 WAIT {settle_ms}
740 PRINT "Last good coarse value = " & last_good
750 PRINT "First bad coarse value = " & first_bad
760 PRINT "Last good fine value = " & fine_good
770 PRINT "First bad fine value = " & fine_bad
780 PRINT "Suggested conservative $120 = " & recommended
790 PRINT "Estimated peak speed at travel midpoint = " & max_mid_speed_mm_min & " mm/min"
800 RESULT "original_x_accel", original_accel
810 RESULT "last_good_coarse", last_good
820 RESULT "first_bad_coarse", first_bad
830 RESULT "last_good_fine", fine_good
840 RESULT "first_bad_fine", fine_bad
850 RESULT "suggested_x_accel", recommended
860 RESULT "max_tested_accel", max_tested_accel
870 RESULT "theoretical_midpoint_speed_mm_min", max_mid_speed_mm_min
880 REPORT
890 PRINT "Original $120 = " & original_accel & ", suggested $120 = " & recommended
900 LET apply_choice = FORM("$120 was " & original_accel & ", suggested is " & recommended & ". [Apply Suggested] [Keep Original]", 1, 0)
905 IF apply_choice <> 1 THEN GOTO 960
910 SEND "$120=" & recommended TIMEOUT 2000 REQUIRE_OK
915 WAIT {settle_ms}
916 PRINT "Updated $120 to suggested value."
917 RESULT "applied_x_accel", recommended
918 GOTO 990

920 LET recommended = original_accel
930 PRINT "The starting acceleration already sounded bad."
940 PRINT "Keeping recommendation at original $120."
950 GOTO 710

960 SEND "$120=" & original_accel TIMEOUT 2000 REQUIRE_OK
970 WAIT {settle_ms}
980 PRINT "Kept original $120 setting."
985 RESULT "applied_x_accel", original_accel
990 END

1000 SEND "$120=" & current_accel TIMEOUT 2000 REQUIRE_OK

1080 LET answer = FORM("Tested $120=" & current_accel & ". [Bad or Skip] [Still Clean]", 1, 0)

9000 PRINT "Test cancelled."
9010 END

13. Example: X-Axis Acceleration Throughput Sweep

This sweeps X acceleration ($120) from {start_accel} upward in steps of {accel_step} at doubling stroke lengths from 1 mm through {max_distance} mm — 1, 2, 4, 8, 16 and 32 mm by default — running a fixed batch of {batch} back-and-forth passes at each level and timing it. For each distance it stops as soon as throughput stops meaningfully improving (the "plateau"), then moves to the next. The result is a family of throughput curves plus a plateau-based $120 recommendation that can be applied or ignored at the end.

What counts as the plateau: after each charted point the script measures the percentage throughput gain over the previous step. When {plateau_streak} consecutive steps all gain less than {plateau_pct}%, the curve has flattened for that distance and the sweep stops there — higher accelerations aren't tested. Requiring a streak (not one flat step) stops a single noisy reading from ending the sweep early. Past the plateau is the diminishing-returns zone where throughput gains are smaller than the run-to-run noise; that's also where the machine starts to struggle, so it's deliberately left untested. Raise {plateau_pct} to stop sooner, lower it to demand a firmer plateau; set {max_accel} lower as a hard ceiling if you want to guarantee it never tests above a value you already distrust.

Reading it: the short strokes are pure triangular moves that may never reach the $110-derived cruise speed, while the longer strokes have enough travel to expose where acceleration stops materially affecting total time. The test ends the distance sweep when the calculated run-up distance is reached, so the longest completed stroke is the most representative of sustained throughput. The chart overlays each measured throughput line with the theoretical peak velocity each stroke can reach at that acceleration, capped by $110. Throughput alone doesn't prove the machine executes a given acceleration without losing steps under load; confirm the proposed setting with a real cut and your separate max-rate test. The original $120 is restored (or the recommendation applied) at the end, so a run never strands the machine at a high value. 

; TITLE: X-Axis Acceleration Throughput Sweep
; AUTHOR: NicholasL
; VERSION: 12
; DESCRIPTION: Sweeps $120 from {start_accel} to {max_accel} in {accel_step} steps at doubling stroke lengths from 1 mm up to {max_distance} mm.
; DESCRIPTION: Feed and cruise ceiling both come from $110 (X max rate) — no separate feed variable. Fixed batch of {batch} passes per step.
; DESCRIPTION: Stops each distance at the throughput plateau ({plateau_streak} consecutive gains under {plateau_pct}%), and stops the whole sweep once a stroke reaches cruise (run-up = v^2/accel).
; VAR start_accel=400
; VAR accel_step=200
; VAR max_accel=8000
; VAR batch=4
; VAR settle_ms=50
; VAR idle_timeout=15000
; VAR plateau_pct=5
; VAR plateau_streak=2
; VAR max_distance=16

10 LET proceed = FORM("X-Axis Acceleration Throughput Sweep\, clear the machine so X can move freely around the current point. Do not switch browser tabs during the test — tab switching throttles the timer and causes false readings. [Begin Test] [Cancel]", 1, 0)
20 IF proceed <> 1 THEN GOTO 9000
30 PRINT "BENCH META title: X-Axis Acceleration Throughput Sweep"
31 PRINT "BENCH META x: accel"
32 PRINT "BENCH META series: distance"
33 PRINT "BENCH META y: mm_per_min, peak_mm_min"
34 PRINT "BENCH META xlabel: Acceleration (mm/s²)"
35 PRINT "BENCH META ylabel: Velocity / throughput (mm/min)"
36 PRINT "BENCH META colorby: distance"
37 PRINT "BENCH STYLE mm_per_min marker: dot"
38 PRINT "BENCH STYLE mm_per_min line: on"
39 PRINT "BENCH STYLE peak_mm_min marker: dot"
40 PRINT "BENCH STYLE peak_mm_min line: off"
41 PRINT "BENCH RECORDS {distance} mm @ {accel} accel"
42 PRINT "BENCH RECORDS {_elapsed} ms"
43 PRINT "BENCH RECORDS {batch} cycles"
44 PRINT "BENCH RECORDS {travel} mm travel"
45 PRINT "BENCH RECORDS avg velocity {mm_per_min} mm/min"
46 PRINT "BENCH RECORDS peak velocity {peak_mm_min} mm/min"
47 PRINT "BENCH RECORDS ramp-up {ramp_up_mm} mm"
48 LET v_start_accel = {start_accel}
49 LET v_accel_step = {accel_step}
50 LET v_max_accel = {max_accel}
51 LET v_batch = {batch}
52 LET v_settle_ms = {settle_ms}
53 LET v_idle_timeout = {idle_timeout}
54 LET v_plateau_pct = {plateau_pct}
55 LET v_plateau_streak = {plateau_streak}
56 LET original_accel = SETTING("$120")
57 LET v_max_rate = SETTING("$110")
58 LET max_x_velocity = v_max_rate / 60
59 LET v_max_distance = {max_distance}
60 LET best_mm_min = 0 : LET best_accel = 0
61 LET best_dist = 0 : LET gain = 0
62 LET peak_mm_min = 0
65 PRINT "Cruise = $110 = " & v_max_rate & " mm/min (" & ROUND(max_x_velocity, 1) & " mm/s). Moves feed at F" & v_max_rate & "."
90 STATUS
92 WAIT v_settle_ms
94 SEND "G21" TIMEOUT 3000 REQUIRE_OK
100 SEND "G91" TIMEOUT 3000 REQUIRE_OK
110 LET current_distance = 1

200 IF current_distance > v_max_distance THEN GOTO 8000
210 LET batch_travel = v_batch * 2 * current_distance
215 LET prev_mm_min = 0 : LET streak = 0
218 LET plateaued = 0 : LET plateau_accel = 0 : LET plateau_mm_min = 0
250 PRINT "Distance " & current_distance & " mm, batch=" & v_batch & " (" & batch_travel & " mm per step)"
300 FOR test_accel = v_start_accel TO v_max_accel STEP v_accel_step
310 LET current_accel = test_accel
320 GOSUB 1000
330 IF plateaued = 1 THEN GOTO 700
620 NEXT test_accel

700 IF plateau_accel > 0 THEN GOTO 706
702 LET plateau_accel = current_accel
704 LET plateau_mm_min = mm_per_min
706 LET best_accel = plateau_accel
708 LET best_mm_min = plateau_mm_min
710 LET best_dist = current_distance
720 PRINT "Distance " & current_distance & " mm: plateau $120=" & plateau_accel & " (" & plateau_mm_min & " mm/min)"
722 LET run_up = (max_x_velocity * max_x_velocity) / plateau_accel
724 IF current_distance < run_up THEN GOTO 870
726 PRINT "Cruise reached at " & current_distance & " mm (>= run-up " & ROUND(run_up, 2) & " mm at accel " & plateau_accel & "). Stopping distance sweep."
728 GOTO 8000
870 LET current_distance = current_distance * 2
880 GOTO 200

1000 SEND "$120=" & current_accel TIMEOUT 2000 REQUIRE_OK
1010 WAIT v_settle_ms
1020 PRINT "BENCH START distance=" & current_distance & " accel=" & current_accel & " batch=" & v_batch & " repeat=1 feed=" & v_max_rate
1025 LET t0 = CLOCK()
1030 FOR pass_index = 1 TO v_batch
1040 SEND "G1 X" & current_distance & " F" & v_max_rate BUFFERED
1050 SEND "G1 X-" & current_distance & " F" & v_max_rate BUFFERED
1060 NEXT pass_index
1070 WAIT_IDLE v_idle_timeout
1072 LET last_ms = ELAPSED(t0)
1074 IF last_ms <= 0 THEN GOTO 1095
1078 LET mm_per_min = ROUND(batch_travel * 60000 / last_ms, 1)
1079 LET peak_mm_min = ROUND(MIN(v_max_rate, SQRT(current_accel * current_distance) * 60), 1)
1080 REM CLAMP bounds the theoretical cruise velocity to the legal feed range (0..$110)
1081 LET cruise_feed = CLAMP(SQRT(current_accel * current_distance) * 60, 0, v_max_rate)
1085 LET ramp_up_mm = ROUND(cruise_feed * cruise_feed / 3600 / (2 * current_accel), 2)
1086 PRINT "BENCH END distance=" & current_distance & " accel=" & current_accel & " batch=" & v_batch & " repeat=1 feed=" & v_max_rate & " mm_per_min=" & mm_per_min & " peak_mm_min=" & peak_mm_min & " ramp_up_mm=" & ramp_up_mm
1087 GOSUB 1200
1088 PRINT "Measured distance=" & current_distance & " accel=" & current_accel & " took=" & FORMAT_MS(last_ms) & " throughput_mm_min=" & mm_per_min & " peak_mm_min=" & peak_mm_min
1090 RETURN
1095 PRINT "BENCH END distance=" & current_distance & " accel=" & current_accel & " batch=" & v_batch & " repeat=1 feed=" & v_max_rate
1096 PRINT "Miss (zero ms) at accel=" & current_accel & "; not charted."
1097 RETURN

1200 REM Plateau detector — one AND condition replaces the nested GOTO ladder
1210 IF prev_mm_min > 0 THEN GOTO 1230
1220 LET prev_mm_min = mm_per_min
1225 RETURN
1230 LET gain = (mm_per_min - prev_mm_min) / prev_mm_min * 100
1240 LET prev_mm_min = mm_per_min
1250 LET streak = streak + 1
1260 IF gain < v_plateau_pct AND streak >= v_plateau_streak THEN GOTO 1280
1270 LET streak = 0
1275 RETURN
1280 LET plateaued = 1
1282 LET plateau_accel = current_accel
1284 LET plateau_mm_min = mm_per_min
1290 PRINT "Plateau at distance=" & current_distance & " accel=" & current_accel & " (gain " & ROUND(gain, 1) & "% for " & v_plateau_streak & " steps)"
1299 RETURN

8000 PRINT "=== Sweep complete ==="
8010 PRINT "Recommend $120=" & best_accel & " (" & best_mm_min & " mm/min on the " & best_dist & " mm stroke) — the plateau, where throughput gains fell below " & v_plateau_pct & "%. Past here is the noisy/diminishing-returns zone, deliberately not tested. Original $120=" & original_accel & "."
8040 LET apply_accel = FORM("Sweep done. Sane $120=" & best_accel & " (" & best_mm_min & " mm/min\, " & best_dist & " mm stroke) — the plateau where gains dropped below " & v_plateau_pct & "%. Higher accelerations were skipped as diminishing-returns/noisy. Confirm with a real cut before trusting it. Apply this\, or keep current? [Apply " & best_accel & "] [Keep " & original_accel & "]", best_accel, original_accel)
8050 SEND "$120=" & apply_accel TIMEOUT 2000 REQUIRE_OK
8060 WAIT v_settle_ms
8070 PRINT "$120 set to " & apply_accel
8080 END

9000 PRINT "Test cancelled."
9010 END

14. Example: FluidNC Startup Flowchart

This script implements the FluidNC sender startup flowchart: open the port, send a status poll to wake the controller, wait for a banner (Grbl … or FluidNC …) or a live-state response (<Idle|…>), then read $30 to confirm two-way comms. A graceful DISCONNECT handles the no-response case.

SEND_DELAY defaults to 0, and WAIT_FOR_LINE provides the blocking wait with its own timeout when pacing is needed.

; TITLE: FluidNC Startup Flowchart
; AUTHOR: GitHub Copilot
; VERSION: 1
; DESCRIPTION: Opens a serial port and runs the recommended FluidNC/GRBL sender startup
; DESCRIPTION: sequence from wiki.fluidnc.com/en/support/gcode_senders.
; DESCRIPTION: Polls with ? after connecting, waits up to {banner_timeout} ms for a banner
; DESCRIPTION: or state response, then reads $30 to confirm two-way comms.
; VAR baud=115200
; VAR banner_timeout=3000
; VAR settle_ms=200

10 REM Open the browser serial port picker and connect
20 CONNECT BAUD {baud}

30 REM ? is a realtime status poll — safe on any firmware state, provokes a response
40 STATUS

50 REM Wait for a startup banner (GrblHAL / Grbl / FluidNC) or a live-state report (<Idle|...>)
60 LET first_line = WAIT_FOR_LINE("GrblHAL|Grbl|FluidNC|<", {banner_timeout})
70 IF first_line = "" THEN GOTO 9000

80 PRINT "Controller responded: " & first_line
90 WAIT {settle_ms}

100 REM Read $30 to confirm full two-way (command + response) comms are working
110 LET max_rpm = READ("$30")
120 PRINT "Max spindle RPM ($30) = " & max_rpm
130 PRINT "Startup complete — add machine-specific steps below."
140 STATUS
150 END

9000 PRINT "No response within " & {banner_timeout} & " ms."
9010 PRINT "Check baud rate ({baud}) and USB cable, then retry."
9020 DISCONNECT
9030 END
